# Plan 06-02: Prompt Haiku con imperfezioni umane + output JSON multi-msg

<objective>
Riscrivere SYSTEM_PROMPT e build_user_prompt in response-analyzer.py per generare risposte con imperfezioni umane (come AMBRA) e output in formato JSON array di 2-3 messaggi separati.
</objective>

## Tasks

<task id="1">
<title>Riscrivere SYSTEM_PROMPT con imperfezioni umane</title>
<read_first>
- wa-intelligence/response-analyzer.py (linee 53-91 — SYSTEM_PROMPT attuale)
- research/s73_messaging_v2.md (template per archetipo)
- tools/backstory_luca_ferretti.md (persona)
</read_first>
<action>
Sostituire SYSTEM_PROMPT in response-analyzer.py con una versione che istruisce il modello a:

1. **Formato output**: SEMPRE JSON array di 2-3 messaggi separati:
```json
{"messages": ["primo msg", "secondo msg"]}
```

2. **Imperfezioni OBBLIGATORIE** (mix casuale, non tutte insieme):
   - "ciao" con c minuscola (MAI "Ciao" all'inizio)
   - Spazio prima di "?" circa 30% delle volte ("come va ?")
   - A volte doppio "??" (circa 20%)
   - Niente maiuscola dopo punto circa 40% ("ok. ti mando i dettagli")
   - Abbreviazioni occasionali: "cmq", "xché", "nn" (solo 10%, non esagerare)

3. **Intercalari OBBLIGATORI** (almeno 1 per risposta):
   - "guarda", "senti", "dai", "niente", "diciamo", "praticamente", "insomma"

4. **Stile multi-messaggio**:
   - Msg 1: apertura breve (saluto + aggancio)
   - Msg 2: contenuto principale (risposta alla domanda/obiezione)
   - Msg 3 (opzionale): chiusura con domanda o call-to-action

5. **Regole assolute** (invariate):
   - Fee SEMPRE €1.000
   - MAI menzionare CoVe/Claude/AI/algoritmo
   - MAI inventare veicoli o prezzi
   - Se NEGATIVE → non rispondere
   - Firma: solo "Luca" (MAI "— Luca", MAI "Cordiali saluti")

6. **Tono per archetipo** (invariato dal prompt attuale, ma adattato allo stile informale):
   - NARCISO: esclusivita ma linguaggio colloquiale
   - RAGIONIERE: numeri precisi ma tono da "collega"
   - TECNICO: dettagli ma senza formalismo
   - RELAZIONALE: calore, come parlare con un amico
   - BARONE: rispetto ma non servilismo

Il nuovo SYSTEM_PROMPT deve essere chiaro che il modello NON deve MAI produrre testo fuori dal JSON. La risposta DEVE essere SOLO il JSON.
</action>
<acceptance_criteria>
- SYSTEM_PROMPT contiene la parola "messages" (formato JSON output)
- SYSTEM_PROMPT contiene "minuscola" (istruzione imperfezioni)
- SYSTEM_PROMPT contiene "guarda" o "senti" o "intercalari"
- SYSTEM_PROMPT contiene "JSON" (formato output)
- SYSTEM_PROMPT NON contiene "RISPOSTA_A" e "RISPOSTA_B" (vecchio formato rimosso)
- SYSTEM_PROMPT contiene "1.000" (fee corretta)
</acceptance_criteria>
</task>

<read_first>

</read_first>
<action>
Riscrivere `parse_llm_responses()` per:

1. Tentare di parsare il testo come JSON: `json.loads(text)`
2. Se JSON valido con chiave "messages" (array di stringhe):
   - Ritornare un singolo oggetto: `[{'label': 'LLM_MULTI', 'text': json.dumps(parsed), 'messages': parsed['messages']}]`
3. Se JSON non valido → fallback: provare a estrarre JSON da markdown code blocks (```json...```)
4. Se ancora fallback → usare il testo intero come singolo messaggio: `[{'label': 'LLM_SINGLE', 'text': text.strip()}]`

Il campo `messages` (array) è usato da auto_approve_and_send per decidere se chiamare /send o /send-multi.
</action>
