# Plan 06-01: Multi-messaggio con delay + typing indicator

<objective>
Aggiungere endpoint `/send-multi` al wa-daemon che invia 2-3 messaggi separati con typing indicator e delay 3-8s tra ognuno, simulando il comportamento umano di AMBRA.
</objective>

## Tasks

<task id="1">
<title>Aggiungere endpoint /send-multi a wa-daemon.js</title>
<read_first>
- wa-intelligence/wa-daemon.js (linee 440-498 — endpoint /send esistente)
</read_first>
<action>
Aggiungere nuovo endpoint HTTP POST `/send-multi` al server HTTP (porta 9191) di wa-daemon.js.

Il payload è:
```json
{
  "phone": "393281536308",
  "messages": ["primo msg", "secondo msg", "terzo msg"],
  "dealer_id": "stile_car_01"
}
```

L'endpoint deve:
1. Validare phone e messages (array 1-5 elementi)
2. Controllare daily limit
3. Per ogni messaggio nell'array:
   a. Inviare `chat.sendPresenceUpdate('composing')` — typing indicator
   b. Attendere delay proporzionale alla lunghezza del messaggio: `Math.max(3000, Math.min(8000, msg.length * 50 + randomJitter))` dove randomJitter = Math.random() * 2000
   c. Inviare il messaggio con `client.sendMessage(chatId, msg)`
   d. Incrementare DAILY_SENT
   e. Loggare su DB (tabella messages) con direction='OUTBOUND'
4. Dopo l'ultimo messaggio: `chat.clearState()` per rimuovere typing
5. Aggiornare conversations.current_step e last_contact_at
6. Ritornare JSON con status, msg_ids[], daily_sent

Il delay tra messaggi simula la digitazione umana: msg corto (20 char) = ~3s, msg lungo (200 char) = ~8s.
</action>
<acceptance_criteria>
- wa-daemon.js contiene `req.url === '/send-multi'`
- wa-daemon.js contiene `sendPresenceUpdate('composing')`
- wa-daemon.js contiene `chat.clearState()`
- Il delay tra messaggi è calcolato con `msg.length * 50`
- Ogni messaggio è loggato individualmente nella tabella messages
- Daily limit è controllato PRIMA dell'invio e incrementato per OGNI messaggio
- L'endpoint ritorna JSON con array di msg_ids
</acceptance_criteria>
</task>
